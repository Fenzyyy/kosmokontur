# Реестр ключевых рисков

Реестр относится к собственному плану команды. Обязательный MANDATORY_STRESS не повторно оценивается как отдельный риск.

| ID | Событие | Причина | Период | Параметры модели | Количественное последствие | Владелец | Мера | Остаточный риск |
|---|---|---|---|---|---|---|---|---|
| R1 | Недопоставка Lunar-ISRU | ограниченная фактическая доступность | 2038–2040 | delivery_share D | получить из сценарного расчёта: shortage, SL, запас, PV cost | оператор снабжения | резерв Earth-Flex / Earth-Core; заранее согласованный запас | рассчитывается после меры |
| R2 | Задержка Earth-New | construction / commissioning delay | 2035–2038 | stage dates, in_service, available capacity C | получить повторным расчётом задержанного ввода: т дефицита, CAPEX, SL | инвестиционный менеджер | investment gate + сохранение гибкого наземного канала | рассчитывается |
| R3 | Рост цены наземных каналов | ценовой шок | 2038–2039 | price_multiplier A/B | PV cost, procurement, possible plan change | procurement | гибкость B, предварительное резервирование, альтернативный источник | рассчитывается |

## Как рассчитывать последствия

Для каждого риска выполняется отдельный исследовательский сценарий на копии исходного набора:

1. Зафиксировать baseline plan.
2. Изменить только параметры данного риска.
3. Выполнить fuel_model.engine.evaluate().
4. Зафиксировать shortage_total, shortage_critical, min_sl_total, min_sl_critical, inventory / reserve gap, CAPEX, OPEX, procurement, PV cost, hard violations и изменение сроков ввода при инвестиционных рисках.
5. Повторить расчёт после меры.
6. Residual risk = последствия после меры при тех же условиях риска.

## Правило оценки

Вероятность не назначается как установленный физический факт без источника. Если статистики нет, используется явно обозначенный сценарный диапазон или допущение. Численное последствие должно быть взято из расчёта модели, а не из произведения условных баллов риска.

## Что показать на защите

Для 3–4 наиболее существенных рисков показать цепочку: событие → изменение параметра → изменение поставки/запаса → изменение сервиса → изменение стоимости → мера → остаточный эффект.
